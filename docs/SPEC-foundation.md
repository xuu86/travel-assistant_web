# SPEC-foundation：共享基础能力

> 版本：v0.1｜状态：已批准｜批准日期：2026-10-27  
> 本规格已于 2026-10-27 获用户批准。批准仅确认规格边界；计划、任务拆分和编码仍按各阶段门禁分别审阅。

## 0. 已批准假设与后续待决事项

1. 本工作区是独立项目；不把原 `travel-assistant/backend` 中未经验证的草稿直接当作实现或契约来源。
2. `foundation` 为 Web API 与前端提供稳定的共享概念；API 契约是跨端事实来源。TypeScript 类型采用生成还是手写镜像，留待计划阶段结合 Q-013 决定。
3. 业务日期使用 `Asia/Shanghai`；时间戳使用带时区的 UTC。系统本机时区不得改变行程日期语义。
4. 城市注册表至少包含已确认的上海、苏州、无锡、嘉兴、杭州；任何坐标需注明 WGS84、来源和核实状态。注册表不表示外部数据供应商已覆盖该城市。
5. 对 Q-009 的建议：演示数据只允许在明确选择的演示／测试上下文出现，并始终保留 `demo` 状态；真实查询失败时不得静默以演示数据冒充真实数据。是否允许生产界面提供显式演示模式仍需在本规格审阅时确认。

## 2. Objective 与范围

### 目标

为各模块提供一致、可校验、可追溯的基础契约，避免不同模块各自解释日期、金额、坐标、来源和供应商状态。成功条件：五个试点城市在注册表中可被识别；日期转换跨 UTC 日界时仍遵从北京时间；未知金额不被转为零；数据缺失、部分覆盖、未配置、限流、不可用和演示数据可区分；服务端配置或内部错误不会泄露密钥及敏感细节。

### 首版包含

- FastAPI/Pydantic 后端共享契约及前端消费 API 契约的边界约定。
- 配置加载与启动校验的通用机制；供应商专属配置由各 provider 模块定义。
- 通用来源、核实状态、结果状态、公共错误和请求关联 ID。
- `Asia/Shanghai` 业务日期工具、带时区 UTC 时间戳规范及可替换时钟。
- WGS84 城市中心注册表、五个试点城市及注册表条目来源／核实元数据。
- 统一的金额基础语义：整数分；未知值为 `null`；禁止以浮点数承担金额运算。

### 首版不包含

- 天气、交通、酒店、活动、景点或地图的真实查询及供应商适配。
- 业务模块的推荐、行程、预算计算、账号授权、文件导入或持久化。
- 未经确认的行程人数、天数、预算上下限等业务限制（Q-006）。
- 供应商缓存、限流策略、重试策略、演示数据回退策略的具体实现；这些由对应模块 SPEC 定义，遵循已批准的公共状态语义。
- 公网部署、云端账号／同步、支付、订购或外部平台跳转。

## 3. 输入输出契约

### 输入

| 字段／对象 | 类型 | 必填 | 空值语义 | 校验 | 来源／权限 |
|---|---|---:|---|---|---|
| 应用配置 | 环境变量解析后的设置对象 | 启动所需项按环境决定 | 可选 provider 配置缺失表示未配置，不等于请求失败 | 类型、格式、安全约束；未知密钥不得回显 | 服务端进程；不经公共 API 输出 |
| `city_id` | 稳定字符串 ID | 查询城市时必填 | `null` 不代表默认城市 | 必须匹配已登记条目；未知 ID 返回可识别校验错误 | 请求输入；业务模块决定对用户的交互 |
| 业务日期 | ISO 8601 `YYYY-MM-DD` 日期 | 依模块契约 | 缺失由调用模块解释，不自动替换系统日期 | 解析为无时区 `date`；与时间戳严格区分 | 客户端请求或模块推导，需保留原请求范围 |
| 时间戳 | RFC 3339/ISO 8601 datetime | 产生时间／有效时间时必填 | 不允许无时区 datetime | 输入须含时区；输出规范化为 UTC | 服务端时钟或来源数据；来源时间不得被查询时间覆盖 |
| 金额 | 整数 `amount_fen` | 金额已知时必填 | `null` 表示未知／未提供；`0` 表示明确为零 | 整数分；拒绝布尔值、浮点数、非有限数和负值（除非具体模块另有经批准的退款语义） | 用户或来源；须附对应来源／核实状态 |
| 地理坐标 | `latitude`、`longitude` 数值 | 城市中心坐标必填 | 缺失表示未有可用坐标，不填 0 | 纬度 -90..90、经度 -180..180；坐标系固定 WGS84 | 城市注册表；须保留来源和核实时间 |

### 输出

| 对象 | 字段／语义 | 可空 | 来源／时间 | 是否持久化 |
|---|---|---:|---|---:|
| `CityRecord` | `id`、`name`、`province`、`center`、`coordinate_system`、`is_pilot`、来源、核实状态／时间 | 省份或元数据仅在契约允许时可空；已启用城市的中心坐标不可空 | 注册表记录来源与核实时间；固定 `WGS84` | 首版静态注册表，不写用户数据 |
| `SourceRef` | 稳定来源 ID、展示名、可公开引用的来源地址（如适用）、取数时间、数据有效区间／署名要求（如适用） | 地址、有效区间可空；不得因缺失伪造 | 原始 provider／用户输入；原始有效时间与本次查询时间分开 | 仅由调用模块按需求保存 |
| `ResultEnvelope[T]` | `state`、`items`、`sources`、`queried_at`、`request_id`、用户可读提示、可选覆盖范围和公共错误 | 来源、覆盖范围、错误按状态可空；`items` 始终为空数组或有类型的项目列表 | 每个来源保留各自时间；`queried_at` 使用 UTC | 本模块不持久化 |
| `PublicError` | 稳定错误码、简短安全提示、是否可重试 | 可重试性依具体错误定义；不得输出堆栈／密钥 | 服务端映射的安全错误信息 | 不持久化；安全日志只记录错误码和 request ID |
| `request_id` | 单请求关联 ID | 不可空 | 服务端生成或经校验地传播 | 可写脱敏日志；不得携带用户信息或密钥 |

### 建议公共结果状态（待本规格批准后冻结）

- `live`：收到真实来源返回的数据；不单独证明数据完整、最新或准确。
- `partial`：只覆盖部分请求范围；必须附可获得的实际覆盖范围和缺失范围，不得用旧数据补齐。
- `empty`：请求成功但没有返回项目；不得表述为“确定不存在”。
- `demo`：测试／演示数据；必须清晰标识，不能与 `live` 混合后作为真实结果呈现。
- `unconfigured`：对应能力没有有效供应商配置。
- `no_coverage`：请求地区／日期超出已知覆盖范围。
- `rate_limited`：供应商或本地额度／限流阻止请求；不得因此自动付费或切换收费来源。
- `unavailable`：供应商超时、故障或网络不可用。
- `policy_unavailable`：权限、政策或服务资格导致能力不可用。

`state` 不得用单一布尔字段替代；各模块可以增加模块域错误码，但不得改变上述状态的公共语义。真实数据状态与字段核实状态是两个维度，不能相互替代。

## 4. 状态与错误

| 状态／错误码 | 触发条件 | 用户提示原则 | 可重试 | 部分结果 |
|---|---|---|---:|---:|
| `unconfigured` | 可选 provider 配置缺失 | 说明能力未配置；不暗示查询成功 | 不自动重试 | 否，除非其他独立来源已有结果 |
| `no_coverage` | 城市／日期超出已确认覆盖 | 显示实际请求和覆盖边界（若已知） | 覆盖改变后可再查 | 仅保留有来源的部分 |
| `rate_limited` | 已达供应商／本地限额 | 表明受额度限制；不购买、不自动计费回退 | 按供应商 SPEC 决定 | 允许其他独立来源部分结果 |
| `unavailable` | 超时、网络或供应商故障 | 显示能力暂不可用；不暴露内部异常 | 由 provider SPEC 限次定义 | 不影响其他模块／来源的既有结果 |
| `policy_unavailable` | 权限或供应商政策阻止访问 | 显示配置／服务权限问题 | 修复权限后可再查 | 允许不依赖该来源的结果 |
| `empty` | 成功响应中项目为空 | “未查询到结果”而非断言不存在 | 依查询条件处理 | 否 |
| `partial` | 请求区间或数据项不完整 | 同时展示请求范围、已覆盖范围和缺失部分 | 由 provider SPEC 决定 | 是 |
| `CONFIG_INVALID` | 必需配置格式错误或违反安全约束 | 服务启动失败；不得在 API 或日志明文回显配置值 | 修正配置后重启 | 否 |
| `VALIDATION_ERROR` | 公共契约输入不合法 | 返回字段级安全提示，不含内部路径 | 修正输入后可重试 | 否 |
| `INTERNAL_ERROR` | 未预期内部异常 | 仅返回通用提示及 request ID | 视操作幂等性而定 | 不返回不可信的部分数据 |

错误响应不得包含 traceback、绝对路径、环境变量值、密钥、完整请求头或原始敏感 payload。服务端每个请求有唯一 request ID；独立模块故障须相互隔离，不把一个 provider 的错误伪装为全局结果。

## 5. 权限、隐私与数据保留

- `foundation` 不认证用户、不决定 owner scope；由 `auth` 模块负责身份与隔离。
- 不接收或持久化原件、OCR 全文、凭证、完整行程或密码。
- 服务端密钥只在服务端进程读取；不得放入前端配置、OpenAPI 示例、公共状态接口、异常或日志。
- `.env`、`.env.*`、上传目录、行程、凭证、日志和测试输出按安全手册忽略；只允许提交空值 `.env.example` 模板。
- 日志限于 request ID、模块、状态、耗时、重试次数和脱敏错误码；不记录原文、敏感文件名、完整 URL 查询串或绝对临时路径。
- 公共来源地址如含凭证或用户查询参数，输出前必须移除敏感部分；来源名称／时间不能被删除或伪造来掩盖来源状态。
- CORS 仅允许明确配置的开发／验收前端来源，禁止通配符；CORS 不构成身份认证或上传授权。
- 本模块无用户数据保留期限；通用运行日志按项目安全配置保留，具体期限须在运行／发布规格明确，不自行延长。

## 6. 业务规则与不变量

1. 所有行程业务日期按 `Asia/Shanghai` 计算；绝不使用宿主机默认时区解释业务日。
2. API 时间戳必须带时区，内部统一 UTC；日期-only 字段保持 `date` 语义，不隐式转成午夜 UTC。
3. 城市中心及所有地理坐标的公共契约统一为 WGS84；无来源／未核实坐标不得标记为已核实。
4. 五个试点城市必须可通过稳定 ID 识别；城市注册表不代表城市的天气、地点或报价数据已经可用。
5. 金额只使用整数分；`null` 与 `0` 明确区分；元与分转换使用 Decimal 或明确的舍入规则，禁止二进制浮点静默舍入。
6. 来源事实至少保留来源标识和对应的取数／有效时间；用户输入、估算、演示、真实来源须用不同核实／来源标记表达。
7. `empty` 不等于不存在；`unconfigured`、`no_coverage`、`rate_limited`、`unavailable`、`policy_unavailable` 不可合并成一个模糊失败状态。
8. 不得静默以 demo 替代 live；失败分支不得伪装成真实能力已完成。
9. 所有公共错误均为安全、稳定、可测试的契约；内部异常映射不回传原始堆栈或秘密。
10. 所有设置均由显式配置和校验产生；非安全可选 provider 未配置时应用仍可启动并报告 `unconfigured`，安全／结构性配置错误时关闭失败（fail closed）。

## 7. 依赖与配置

- **内部依赖：** 无。Foundation 不导入天气、交通、模型、存储或账号模块。
- **公开依赖：** Web API 契约、城市注册表只读接口、北京时间／UTC 工具、配置读取接口、来源与错误类型。
- **后端框架：** FastAPI + Pydantic（D-006、D-008）；具体锁定版本等待 E-009 核实与批准计划。
- **外部供应商：** 无。
- **配置项：** 通用运行环境与允许来源的配置由本 SPEC 定义；具体变量名在计划阶段统一命名。各 provider 的 Key／URL 由其模块 SPEC 定义，真实值只通过本机私密配置注入。
- **重试／缓存／限流：** Foundation 不执行；状态值由 provider adapter 归一化，次数与 TTL 在各 provider SPEC 规定。
- **测试替身：** 注入固定时钟、临时设置对象、内存城市 registry、fake provider state；测试不得依赖真实密钥、外部网络或真实旅客数据。

## 8. 项目结构与代码风格

建议的实现落点（最终文件清单由获批计划确定）：

```text
backend/app/core/
  config.py
  contracts.py
  errors.py
  time.py
  cities.py
backend/tests/unit/
  test_contracts.py
  test_config.py
  test_time.py
  test_cities.py
frontend/src/shared/
  api-contracts.ts
```

- Python 3 类型注解；Pydantic 模型集中定义公共边界；业务逻辑不塞进 API router。
- 函数／字段用 `snake_case`，类用 `PascalCase`，常量用 `UPPER_SNAKE_CASE`；模块错误码保持稳定、可检索。
- 不使用 `Any` 掩盖外部输入验证；输入边界显式校验；时钟与配置通过依赖注入便于测试。
- 前端类型不得独立漂移；OpenAPI 类型是否生成由 Q-013 的计划决策冻结。

示例（展示金额空值语义，不是已存在代码）：

```python
from pydantic import BaseModel, ConfigDict, Field


class MoneyAmount(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

    amount_fen: int | None = Field(default=None, ge=0)
```

`amount_fen=None` 表示未知／未提供；`amount_fen=0` 表示明确为零。转换“元”输入时另行采用 Decimal 和明确舍入规则，不接受浮点输入作为权威金额。

| 错误安全与关联 ID | 输入校验失败、模拟内部异常 | 公共错误码稳定；响应无 traceback／绝对路径／秘密；日志含同一 request ID | API 集成 | 脱敏响应与日志断言 |
| 供应商故障隔离 | 一个 fake provider 抛超时，另一个返回成功 | foundation 不承担聚合；调用模块可保留独立成功结果并标记故障来源 | 集成（依赖模块） | 集成测试报告、request ID |
| 无前端 Key | 构建前注入仅服务端 fake secret | 前端 bundle、公共状态响应、日志和错误响应均无该值 | 构建／静态扫描 | AC-36 扫描报告 |

**验收映射：** AC-01（五城与北京时间）、AC-06（请求与实际覆盖状态公共表达）、AC-25（配置／额度／政策状态可区分）、AC-28（request ID 与模块故障隔离契约）、AC-36（密钥和敏感日志边界）。AC-06、AC-25、AC-28、AC-36 还需各责任模块按其 SPEC 完成端到端证据；Foundation 单测通过不等于对应全局 AC 完成。

**不得据此宣称完成：** 真实供应商调用／覆盖、真实城市坐标来源核实、真实天气／活动／路线数据、OCR、模型、地图、局域网安全验收，或整个 Web 首版完成。

## 12. 三层边界

- **Always：** 保留来源和时间；区分未知与零、空结果与无覆盖；日期按北京时间解释；金额用整数分；错误安全且有 request ID；任何可选能力未配置时如实报告。
- **Ask first：** 新增外部依赖、改技术栈、改变状态语义或城市范围；把 demo 变为默认回退；引入未批准业务上限；任何配置可能暴露到客户端；调整数据保留、公开仓库或部署边界。
- **Never：** 用旧数据／演示数据冒充真实；把未知金额当 0；将无结果说成确定不存在；使用机器本地时区替代北京时间；泄露密钥、密码、原件、敏感 payload 或绝对临时路径；以直线距离伪装成真实路线。
