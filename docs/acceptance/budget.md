# Budget 验收记录

> 日期：2026-10-27（北京时间）  
> 范围：Capability Map `budget` 的本地计算与导入流程；不代表住宿／机票真实报价、云端持久化或 Web 首版整体完成。预算草稿的浏览器本地恢复与 owner 隔离由 [登录与本地操作保留验收](auth-local-storage.md) 验收。

## 结论

**预算模块实现与本地自动化验收通过。** 已交付严格费用契约、纯预算计算、`POST /api/budget/calculate`、响应式预算表单与摘要，以及 AC-08 至 AC-11 流程证据。计算 API 只处理请求快照、不落盘、不调用供应商；前端预算草稿由 `auth`／`local-storage` 按 owner 保存在当前浏览器 IndexedDB。

## 实现范围

- 费用类别、EvidenceState、完整度、整数分金额与唯一费用／预订主项验证。
- 明确区分未设置／未知（`null`）和 0；未知金额不参加确定结余，已知超支可返回最低超出额。
- 剩余可安排仅按总预算减已支付；预计结余另扣待支付估算和人工预留金。
- 300,000 分预留金提醒仅在预留金为 `null` 时展示；不会自动创建金额。
- 元金额用十进制字符串精确解析，拒绝超过两位小数和超出安全整数范围的金额。
- 用户补填的未报价住宿／往返交通显示“用户填写，非平台报价”，证据状态保持 `user_provided`。
- 真实平台报价、预订修改与重复订单去重不属于预算计算；预算草稿本地恢复和身份隔离由 `auth`／`local-storage` 负责。

## 安全与数据边界

- 集成测试确认 request ID 在响应体与 `X-Request-ID` 一致，重复费用返回统一 `VALIDATION_ERROR`。
- 合成 sentinel 金额、行程 ID 和预订 ID 不出现在请求日志中。
- 使用固定合成 ID 和金额进行测试；无真实费用、订单、密钥、行程文件或供应商请求。
- 本地 Vite `/api` 代理只转发到 `127.0.0.1:8000`；没有公网监听、DNS 或 GitHub remote 配置。

## 2026-11-16 车票订单导入验收

- 支持 Word `.docx`、PDF、JPG/JPEG、PNG；不支持旧版 `.doc`。限制为文件 ≤20 MiB、DOCX 解压 ≤100 MiB/5,000 个条目、PDF ≤50 页、图片 ≤40 MP、文本 ≤2,000,000 字符。
- DOCX 使用 Mammoth 提取文本；PDF 使用 PDF.js，扫描件与图片使用浏览器内 Tesseract OCR。订单文件和 OCR 文本不发送后端；OCR Worker、WASM 与简体中文语言数据由构建时复制到同源静态目录。
- 用户先核对金额候选与支付状态，再确认新增一条可编辑的往返交通费用。明确实付/支付标签默认“已支付”，一般票价/订单金额默认“预计待支付”；导入不验证外部订单真伪或支付完成情况。
- 原文件、OCR 全文、候选列表、进度和错误不会持久化；确认后的费用草稿通过 IndexedDB owner 分区恢复。重复导入不自动识别或合并。
- 定向单测覆盖 DOCX/PDF/图片解析调用、超限文件、PDF 页数/图片像素限制、OCR 中文间隔归一化、候选排序与付款状态添加；预算目录 24 项单测通过，桌面/移动 E2E 6 项通过，类型检查、相关 ESLint 与生产构建通过。
- 桌面 Chrome 使用合成“实付款：￥128.00”图片完成真实 Tesseract OCR 冒烟，核对窗口识别为 ¥128.00 / 实付款并默认选中“已支付”；Worker、WASM 与语言数据请求全部由本站返回，无 HTTP 错误。此样例不代表真实订单识别率评估。
