# 目的地优先工作流：能力图提案

> 状态：能力图与 SPEC v0.1 已批准；实施计划待审阅。上述批准不等于任务清单或代码实施获批。

## 目标

打开应用后先输入目的城市并确认；之后才能进入预算、天气或交通。目的城市在这些视图间共享，但只保存在当前页面会话，不写入 URL、后端或持久化存储。

## 建议能力边界

| 能力 ID | 职责 | 依赖 |
|---|---|---|
| `destination-workspace`（拟新增） | 捕获并校验目的城市、控制工具解锁、在视图间传递当前目的地；不查询供应商、不计算预算、不持久化 | foundation、budget、weather、transport |
| `budget`（已有） | 展示当前目的地上下文并执行现有预算快照计算；金额公式和 API 不变 | foundation |
| `weather`（已有） | 仅将已注册城市映射到现有 `city_id`；未注册城市显示明确的暂不支持状态，不调用天气 API | foundation |
| `transport`（已有） | 将当前目的城市预填为终点；起点和查询条件仍由用户填写，票价与路线边界不变 | foundation |

依赖方向：`destination-workspace` → `budget`、`weather`、`transport`；三项查询模块不反向依赖工作区。

## 流程草案

1. 初始页面只有目的城市输入和继续操作；城市为空或无效时，不能进入三个工具。
2. 确认后进入工作台，预算／天气／交通导航可用，当前目的城市持续显示。
3. 用户可主动更改目的城市；更改后清除与旧目的地绑定的天气和交通查询结果，不改写预算金额或费用。
4. 目的城市只能从 foundation 注册表中的上海、苏州、无锡、嘉兴、杭州选择；天气复用对应 `city_id`，不接受注册表外地点。
5. 刷新页面后目的地不保留；不引入 IndexedDB、账号、行程持久化或供应商能力。
