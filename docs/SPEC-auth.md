# SPEC-auth：游客与测试账号登录

> 版本：v0.1｜状态：待审阅｜对应已批准 Capability Map 的 `auth` 模块

## 1. 元数据

- **关联决策：** D-024、D-035；待决 Q-008
- **依赖模块：** `foundation`
- **被依赖模块：** `local-storage`、`imports`
- **范围：** Web 本地测试账号身份，不是正式云账号；不实现微信登录或服务端行程同步。

## 2. 目标与范围

游客可以免登录使用应用。用户也可以用五个预设测试账号登录；退出或切换账号后，再次登录同一账号仍可恢复该账号之前保存在本浏览器中的行程。身份只用于本地数据分区，不声称已通过线上身份验证或支持跨设备同步。

首版包含登录、登出、游客身份、当前身份恢复和账号切换时的数据隔离。不包含公开注册、找回密码、第三方登录、账号绑定、游客数据迁移、云端身份或跨设备同步。

## 3. 契约与行为

- `GET /api/v1/auth/session`：返回匿名游客或已认证主体摘要；不返回凭据或密码信息。
- `POST /api/v1/auth/login`：接收用户名和密码；成功返回稳定的非敏感 `owner_id`、显示名与短期会话。失败使用统一错误，不区分用户名不存在与密码错误。
- `POST /api/v1/auth/logout`：幂等撤销当前会话并清除客户端认证状态；随后进入游客身份。
- 测试账号从后端本机/部署环境的受控配置载入，密码仅以带盐、抗暴力破解的哈希保存；密码和哈希不得写入仓库、日志或公开错误。
- 请求应限流；会话使用 HttpOnly、SameSite Cookie。开发 HTTP 场景可关闭 Secure，生产环境必须启用 Secure。CSRF 防护与允许来源须匹配项目部署边界。
- 客户端不得把原始用户名、密码、会话凭据写入 localStorage、IndexedDB、URL、埋点或错误上报。
- 登录或切换账号后只展示新身份分区。登出不删除该身份已保存的数据，也不自动将游客数据并入账号；重新登录同一账号恢复其分区。

## 4. 状态与错误

| 状态 | 行为 |
|---|---|
| 游客 | 可继续使用；所有本地资源归属游客分区 |
| 已登录 | 显示非敏感账号摘要；本地资源只读写该账号分区 |
| 凭据错误 | 显示通用登录失败；不泄露账号是否存在 |
| 会话失效 | 清除认证状态并转为游客；不清除任何本地分区 |
| 限流／服务不可用 | 显示可恢复错误；保留当前页面草稿，不清理本地数据 |

登录失败不得改变当前身份或已显示草稿。切换账号前后不得串读、串写或误删其他主体数据。

## 5. 项目结构与实现约束

- 后端模块：`backend/app/modules/auth/`，按现有模块拆分 router、service、配置/存储适配与契约。
- 前端身份状态和登录界面：`frontend/src/features/auth/`；与 `App.tsx` 集成时不将认证细节扩散到业务面板。
- 继续使用 React + TypeScript + Vite 与 FastAPI + Pydantic；除非单独批准，不增加依赖或数据库。
- 凭据尚未配置时服务应明确报告不可用，不提供固定演示密码或假登录成功路径。

## 6. 测试策略

- 后端单元/集成：游客主体、有效及无效凭据、通用错误、登出幂等、撤销后访问、限流、密码哈希校验、日志不含密码、缺失配置。
- 前端组件：游客继续、成功登录、失败保留页面状态、登出、启动恢复和账号切换。
- 集成/E2E：游客数据与每个测试账号隔离；登出再登录同一账号可读回已保存数据；账号 A 的数据绝不显示在账号 B 下。
- 命令：后端 `uv run pytest`；前端 `npm run test:unit`、`npm run typecheck`、`npm run lint`、`npm run build`。

## 7. 边界与验收

- **Always：** 通用认证失败信息；仅存密码哈希；按稳定主体标识隔离；登出/切换不清除已保存分区。
- **Ask first：** 改为正式注册或云端账号、跨设备同步、游客迁移、账号绑定、持久化账号数据库或新增高影响依赖。
- **Never：** 仓库内放测试账号密码；明文保存密码；将“选择用户名”当作登录校验；登录失败时清空现有草稿；把本地测试账号描述为正式线上账号。

验收条件：游客无需登录可继续；只有配置的有效测试账号可登录；未知用户与错误密码不可区分；登出与账号切换不泄露或删除其他身份数据；同一账号在同一浏览器重新登录后可恢复其本地行程；源码、日志与构建产物不含账号密码。

## 8. 未决问题

- Q-008：五个账号的用户名、初始密码发放和重置方式由负责人通过私密渠道确定；实现不得自行造出并提交真实凭据。
- 会话绝对有效期及安全 Cookie 的本地/局域网 HTTP 配置需在计划阶段结合既有运行方式冻结。
