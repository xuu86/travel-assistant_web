# 登录与本地操作保留验收

## 功能边界

- 游客无需登录即可使用工作区；已配置测试账号只能通过后端哈希校验登录。
- 行程和工作区输入保存在当前浏览器 IndexedDB，并按服务端返回的 `owner_id` 隔离。游客使用本站点生成的稳定匿名 ID。
- 登出不会删除任何分区；再次登录同一账号会恢复该浏览器保存的操作。游客与账号、账号之间不合并数据。
- 本地保存不等于云端备份：清理浏览器站点数据可能永久丢失本地数据，没有跨浏览器/跨设备同步。
- 服务端会话保存在进程内，存活 12 小时；退出撤销会话，后端进程重启会使现有登录失效，但不删除浏览器快照。
- 工作区目的地或显式返回城市的确认操作会清理当前 owner 的整个工作区快照；登出本身不会清理。
- 天气、地点/地图供应商响应、交通班次与费用结果、AI 对话、上传原文件和未确认订单识别候选不作为已确认工作区事实保存。恢复后外部查询状态按当前规则重新加载。

## 配置测试账号

不得在源码、提交文档、终端录屏或测试报告中加入真实密码。后端 `.env` 保持在忽略列表内，环境变量优先级由 Pydantic Settings 管理。进入 `backend/` 后运行交互式脚本；密码由 `getpass` 读取且不回显，成功时脚本只向标准输出写一份带盐哈希的 JSON：

```powershell
uv run python scripts/configure_test_accounts.py
```

将 JSON 作为单行值配置到仅本机/受控部署环境的 `APP_AUTH_TEST_ACCOUNTS`，或者作为部署 Secret 注入。脚本要求配置五个账号并验证格式、用户名/身份 ID 唯一性及 PBKDF2-HMAC-SHA256 哈希。输出中不含明文密码，但哈希仍是认证配置，不应提交到版本库或公开日志。若 shell 历史/输出捕获不适合处理该值，应通过部署 Secret 管理工具注入，而非写入命令行参数。

没有收到负责人提供的真实五账号资料，本次没有生成或提交账号哈希。因此本地默认状态下登录端点报告未配置，游客功能仍可用。Playwright 使用仅在测试代码/浏览器内存中存在的合成 `alpha`/`beta` fixture 凭据；fixture 不代表真实账号配置验收。

## 部署限制

Vite 开发服务器与 FastAPI 必须同源代理 `/api`；默认 Vite 代理指向 `127.0.0.1:8000`。FastAPI 同源校验要求认证 POST 带有精确匹配请求 host 的 `Origin`。开发环境 Cookie 为 HttpOnly、SameSite=Lax 且非 Secure；生产强制 HTTPS origin 并以 Secure Cookie 运行。会话内存存储目前只适用于单进程本机/局域网测试，不适用多 worker、滚动部署或生产账号系统。
